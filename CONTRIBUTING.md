# Contributing to StockPilot

## Workflow
1. Pick or create an issue before starting meaningful work.
2. Create a feature branch from latest `main`.
3. Commit frequently with meaningful messages.
4. Add/update tests and documentation as part of the same work.
5. Open a pull request and link the issue.
6. Request at least one teammate review.
7. Fix CI/review feedback before merge.
8. Squash only if your team agrees; do not erase useful contribution evidence without a reason.

## PR must explain
- What problem is solved?
- Which component/student ownership does it support?
- What API/database/UI/agent changes were made?
- What tests were run?
- Any security, migration, or environment variable changes?
- Screenshots or Swagger examples where useful.

## Definition of Done
A feature is done when implementation, validation, authorization, tests, API integration, error states, documentation, CI and code review are complete and the author can explain/modify it in the viva.
